# Methodology Timeline

1. Pre-2026-05-04: the early corpus existed before rule #16 was routine.
   The pre-gate campaigns include `pm-live-readiness`, `cron-fill-grounded-truth`, `ws-cron-alignment`, `cross-platform-pilot-b`, `profit-search`, `crypto-pm-probe`, `bankruptcy-operator-0125`, and `llm-narrative-trade-0125`.
   These runs still contain adversarial review artifacts, but the review mostly happens after mutation rather than before launch.
   Paper 2 therefore treats them as retrospective evidence, not as uniformly pre-registered experiments.

2. First observed R0 program gate.
   Earliest file by filesystem mtime: `abelian/runs/2026-05-03-1710-cross-platform-pilot-b/round-0/program-peer-challenge.txt`.
   UTC mtime: `2026-05-04T01:01:07.208905+00:00`.
   This is the first local `program-peer-challenge*.txt` artifact found by scan.
   The file marks the transition from round-level peer critique to program-contract critique.

3. 2026-05-04 gate adoption.
   The R0 gate appears in `pm-10k50k-profit`, `llm-deploy-10k`, and `sycophancy-benchmark`.
   Those gates attack Target, Eval, Metric, scope, and citation authority before R1 execution.
   The shift matters because several later attacks are contract attacks rather than implementation attacks.

4. 2026-05-05 spread.
   `path-c-1week-probe` records 4 R0 challenge files.
   `boundaries-of-retail-prediction-market-trading` records 5 R0 challenge files.
   Both campaigns show that R0 became iterative: challenge, rewrite, re-challenge, then launch.

5. R0 multi-round pattern emergence.
   Path C is the first visible campaign with a v1 -> v2 -> v3 -> v4 re-gate cycle.
   The initial Path C gate logs 18 attacks across c1/c2/c3/c4/d4.
   Later versions narrow the remaining launch-blockers before R1.

6. Paper 2 R0 pattern.
   Paper 2 has `program-peer-challenge.txt` plus v2, v3, v4, and v5 files.
   The prompt-side sequence records 21 -> 6 -> 4 -> 3 -> 1 attacks before R1 launch.
   That history justifies treating R1 as extraction after a contract-hardening phase.

7. Asymmetric peer policy codification.
   The Paper 2 program encodes Stephen Wang's 2026-05-04 directive.
   Claude peer-A owns innovative-grounded proposal, framing, and reviewer-anticipation attacks.
   Codex peer-B owns heavy implementation, transcript mining, recomputation, and verification.
   R1 is assigned to peer-B because the cell is data extraction rather than prose synthesis.

8. Mission-thread adoption.
   Rule #14 requires goal paraphrase, candidate routes, selected route, selection reason, metric delta, and blocker status.
   This turns rejected routes into a durable empirical object rather than discarded brainstorming.
   The R1 `alternative-routes.jsonl` file is mined from those peer and state traces.

9. Commit-gate interaction.
   Rule #2 keeps the focus on goal progress rather than activity.
   Several peer files accept engineering artifacts while still refusing to credit them as profit.
   Recurring subclasses such as `paper-profit-truth`, `eval-false-green-or-metric-gap`, and `capacity-ceiling` preserve that distinction.

10. Retrospective implication.
    Paper 2 combines mostly pre-gate campaigns with later R0-gated campaigns.
    The methodology contribution is the observed formalization of the adversarial loop.
    It is not a claim that every analyzed campaign started from the same launch protocol.

11. How R1 uses the timeline.
    Section 3 cites the timeline to explain why corpus inventory and methodology evolution are separated.
    Sections 4 through 7 use campaign evidence for trading findings.
    Section 8 will use this timeline for the Abelian framework formalization.
